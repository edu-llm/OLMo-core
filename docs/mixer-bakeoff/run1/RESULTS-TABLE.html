4 · Recommendation

Use KDA as shipped, or KDA with the convolution activation removed. Basis: throughput and memory, because cross-entropy is unresolved. The four fla-kernel arms sit within 2% on speed and 0.05 nats on CE; the two custom-kernel Householder arms cost 22% and 29% for no measurable quality.

  • The Householder finding is about the kernel, not the mechanism. R=1 is mathematically identical to the shipped operator — same params, same 2,473,388,544 FLOP/token — yet runs at 0.779× with MFU 32.4% against 41.5%. So kernel overhead alone is 28.6%, while the arity step R=1→R=2 costs a further 10.9%. If R>1 is wanted, chunk the kernel; never ship KDA-Householder at R=1, since the shipped operator is the same model 28.6% faster.
  • R=1 also carries sd 0.04516 — 4× any other arm, on identical mathematics. Suspected kernel-induced instability; n=3 with one outlier cannot prove it. Worth checking against the backend="torch" reference path.
  • The gated convolution is a bound, not a benefit: +0.005 nats against its correct control, for +3.1% peak memory and −2.1% throughput.
  • GDN2 is the largest effect measured (+0.037 nats, worse) and the only one significant under any test. Directional, not settled — and a quality-at-fixed-params result at TPP 1.5, not a verdict on the implementation.

5 · Caveats that travel with every CE number above

  • TPP = 1.5, below the 3–20 academic cluster (budget cut 1,907→1,144 steps to fit the window). Architecture effects measured at low token budgets systematically overstate — measured in-tree, GDN's edge halved 0.0103 nats @1B → 0.0059 @15B. Treat every CE figure as an upper bound on the production effect.
  • Throughput and peak memory are budget-independent and fully valid. They do not inflate the way CE does, which is why they carry the recommendation.
  • A null is a bound, not equivalence. No margin was pre-declared, so no TOST is available; a non-significant contrast licenses only "smaller than the CI half-width".
  • A 0.6B-token run structurally cannot see effects that emerge late in training, or any long-horizon recall advantage. That is a limitation, not a null.
  • Secondary endpoint (sliced_eval) is null throughout: it needs --slice-mask-uri, which this command does not set. Declared, not quietly skipped.
