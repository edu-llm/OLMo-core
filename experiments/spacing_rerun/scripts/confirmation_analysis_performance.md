# CPU analysis performance driver

This engineering driver measures CPU work using genuine prepared metadata and
seeded synthetic saved outcomes. It invokes no model, tokenizer, tensor loader,
training loop or GPU operation. It creates no scientific, source, property,
membership, reporting, production or launch approval. Its small artifact tests
are engineering checks, never an actual benchmark.

The independently accepted R6 v6 implementation retains actual preexec receipt
bytes through available parent returns and exceptions. Its exact acceptance and
commit remain historical bindings. The rejected R7 candidate added optional
original-FD transport for a separately owned outside-namespace retainer. Its
independent review found two rejection-evidence defects. This R8 candidate
corrects those separately owned paths and needs its own
independent review and final integration. The eight native filter, ELF and
read-scope functions, full BOOTSTRAP, 18 numerical functions and six primary
helpers retain their accepted bytes. All earlier reviews, failures and scoped
acceptances remain preserved. They supply no new production or launch approval.

## Optional original-FD transport candidate

`launch_native(invocation, anchor, log_path, *, channel_observer_fd=None)` keeps
the existing v6 available-return API when no bridge is supplied. The driver input,
result and worker observation schemas remain v6. The standalone R7 owner artifact
`native_channel_retainer.py` supplies `create_observer_bridge`,
`OriginalChannelRetainer` and `launch_and_retain`. This module is separately
full-file and function pinned. It does not silently enable transport in ordinary
driver preflight or supply an approved harness. Its runtime loader compiles exact
supplied hash-bound bytes and rejects a symlink or changed source.

The owner first reconciles the authentic original bound diagnostic bucket and
historical starts, then durably reserves the original run/attempt before sbatch.
The retainer starts inside that same accounted Slurm allocation. Each applicable
startup, pre-Session or retainer failure consumes that same reserved slot. The
original max3 never resets. The original design's conflicting pre-submission
retainer wording remains preserved with the explicit root ordering clarification.
Reservation evidence is distinct from a running retainer's registration evidence.
Actual histories, remaining attempts and full-study freeze remain external.

The trusted retainer owns RW duplicate open file descriptions received through
SCM_RIGHTS. It uses `pread` on originals, preserving shared OFD offsets. This is
trusted observer behavior, not kernel-enforced read-only access. Its socket and
sink descriptors never enter the namespace. One explicitly identified sender
bridge may pass the separately reviewed capdrop path into the supervisor only.
The child preexec wrapper closes that known bridge, or observes EBADF if already
closed, before calling the unchanged original Landlock function. The bridge is
excluded from `pass_fds` and absent from BOOTSTRAP/native worker. That closure
inference is not appended to the unchanged kernel receipt or called a new ACK.
Actual capdrop, Linux closure and enforcement proof remain the native owner's
independent integration responsibilities.

The first synchronous handoff carries the original output directory plus the
four anonymous invocation, producer, preexec receipt and custody journal files.
The second carries the original exclusive invocation file and stdout log. The
retainer independently checks exact ordered roles, FD counts, device/inode,
anonymity, file type and original access mode. It rejects aliased objects. No
invocation/channel bytes or native Popen starts before both durable ACKs. Empty
FD creation and handoff are not atomic; an empty original or named-file identity
may remain unavailable if the supervisor dies before its handoff.

Each canonical raw frame binds exact invocation/run/attempt nonces, deployment,
policy, output identity, namespace-labelled launcher PID, sequence and previous
raw message hash. ACKs bind the actual raw frame and binding hashes, and follow
fsync of copied bytes, receipt and directory entries. Production requires actual
Linux SO_PASSCRED/SCM_CREDENTIALS on both endpoints. The receiver checks the sender
UID/GID and observed positive PID in its own namespace, with a supplied expected
PID when known and a consistent observed sender throughout. User-namespace UID0
mapping and host PID expectations must come from actual owner observations.
No arithmetic PID conversion or inherited socketpair SO_PEERCRED substitute is
allowed. Mac tests claim artifact-only transport, never Linux identity proof.

Invocation and native records travel as original raw fragments. Exact offset,
total size, metadata and completed stream hash are checked without reserializing
JSON and calling it an original. Raw frame headers/payloads remain separate from
their receipts and copied epochs. An emitted native fragment is distinct from a
complete hash-verified original emitted stream and from an available-return
native record. A delivery failure can add fields to the available native record
after an earlier emitted stream; their raw identities remain distinct. A missing
final native record is never reconstructed from epochs or controller events.

The R8 rejection observation uses
`p4-original-observer-rejection-observation-v1` for framing and semantic failures.
Before parsing, checking or closing received descriptors, the receiver records
actual header/payload bytes, base64/length/raw hash, available original credential
bytes and every available descriptor fstat identity. Credential fragments retain
their received raw encodings. These observations are explicitly unvalidated.
The sender's declared inode values remain in the original raw payload and never
replace actual receiver identities. An unavailable fstat has a null identity and
its original error; descriptor cleanup records each actual close result. Rejected
registration frames remain rejected, and no ACK authorizes their channel writes.

Retainer semantic exceptions carry that typed observation through `serve` into
the original error byte files and observation JSON. Launcher ACK semantic and
partial-frame exceptions carry the same original received evidence into optional
`observer_rejection_observations` in the native record, NativeLaunchFailure and
its original typed cause. The official adapter additionally writes each original
header/payload and its observation JSON under `observer-rejections`. Export-write
failures preserve the original launch exception and inline bytes. Whitespace in
a noncanonical ACK is retained exactly. No canonical re-encoding substitutes for
the received packet. A first-stage rejection retains null worker PID/status/RSS
and absent invocation-buffer facts. Missing bytes or identities stay unavailable.

The accepted original55 tests and R7's20 transport tests retain full-line bytes.
Four new R8 regressions cover the real five-original SCM_RIGHTS inode mismatch,
noncanonical/wrong-binding/descriptor-bearing/partial ACKs through the official
adapter, unavailable descriptor observations and inline originals after export
failure. The CPU peer and diagnostic copies are independently labelled fixture
evidence. They do not replace original launcher/retainer capture or establish
Linux credential enforcement. Original R7 adversaries/rejection/status, previous
verification failures and all earlier review history remain unchanged.

Transport bounds are 32,768 payload bytes per frame, seven descriptors, 8,192
bytes per raw fragment, 2 MiB per raw record or per sampled channel, 1,024 ordered
messages and 512 capture epochs. The retainer runs for at most 165 requested
seconds, checks its own deadline, and bounds individual frame reads. Reaching a
bound fails closed or marks the sampled bytes capped. These limits do not claim
that an arbitrary large deployment is eligible.

Epoch files retain actual original identity, copied identity, raw bytes/hash,
before/after sizes, prefix conflicts, shrinkage and caps. They are concurrent
non-atomic samples. Bridge EOF, controller EOF and a deadline never prove writer
quiescence. Controller bytes remain explicitly unverified outside observations.
If the supervisor dies, a surviving retainer can continue sampling the same
original objects. If the retainer dies, only already fsynced epochs survive; the
launcher rejects delivery and kills/reaps its owned child using actual wait4
when available. If scheduler/node/storage failure kills the whole allocation,
all anonymous originals can disappear. No outside-job daemon or remote backup
is supplied. Unread or unfsynced tails remain unavailable. Creation-to-journal
crash gaps and incomplete abrupt-failure inventory remain unchanged.

`launch_and_retain` consumes the caller bridge and exports available producer,
receipt, journal and native bytes into a separate new anchored root. Export
failures retain those available originals on the raised exception and preserve
an original NativeLaunchFailure rather than replacing it. These ordinary return
copies never substitute for outside-retainer epochs. Retainer lifecycle errors
are recorded when storage permits; if the summary write fails, its exception
retains the available summary. Neither transport API certifies scheduler custody,
process-tree quiescence, kernel enforcement or completed production accounting.

## Execution, memory and containment

The parent opens the output through component-by-component directory descriptors,
rejecting symlinks. Creation uses anchored descriptors and exclusive files.
Each operation checks its complete current inode chain; a complete registry check
runs at phase completion. Writes are unbuffered or text write-through, so an
exception does not later flush buffered bytes into a moved inode. The registry
retains descriptors for locally opened directories. Imported child directory
claims retain original inode identities and use temporary descriptors only when
the current path matches. No permanent descriptor per output file is required. Failure
records retain original identities and kernel-observed directory custody. File
custody reports whether the current name still matches the created inode; a
separately moved file's unknown current path remains null. Pathname checks cannot
prevent an external rename between a check and syscall. Production prevention
comes from actual read-only data mounts and different output/production devices.
Artifact tests establish detection and truthful custody only.

Before each launch the parent opens its invocation and log files exclusively and
captures their original inode identities with all existing output entries. The
child receives that exact parent baseline and preserves it. Its complete sorted
`p4-output-inode-registry-v1` inventory carries every child-created directory,
file and symlink through the inherited producer channel. The child opens the
result file before serializing its registry, so the result's own original inode
is included without a content-hash cycle. The parent receives the original claims
before reading pathname results, reconciles each current anchored chain and
retains original identities on failure. Identical bytes at a replacement inode
do not satisfy custody. A moved original file with no observed current path
retains null custody rather than an invented location.

A fresh `python -I -B -S` worker compiles captured application source buffers.
Captured package imports cannot fall back to uncaptured disk modules. Exact
interpreter/deployment/payload identities and a unique invocation nonce accompany
all output. Original source and retained deployment bytes are rechecked through
completion. Application code buffering and external runtime/deployment custody
are distinct guarantees. The latter still needs the actual reviewed deployment.

Before `execve`, Landlock ABI3 or later restricts reads to the exact immutable runtime census,
captured application originals, disclosed immutable data files, data roots and
output. Directory lookup rights grant no additional file reads. One exact
`/proc/<actual-child-PID>/maps` file is readable; no broad proc file/FD allowance
is granted. The preexec receipt binds the actual PID, invocation, policy, exact
rules and syscall outcomes through an anonymous descriptor that closes before
application execution. Root authenticates original invocation/scheduler custody
separately.

The ruleset handles all filesystem rights through TRUNCATE. WRITE_FILE, TRUNCATE,
MAKE_DIR, MAKE_REG and MAKE_SYM are granted only under the output root. Runtime,
data, proc maps and ancestor rules grant no write rights. Removal, cross-directory
REFER and other creation rights remain denied globally. This closes newly opened
writable proc-memory and outside-output file routes. Already inherited anonymous
invocation/producer/receipt descriptors are separate retained channels. The
supervisor creates all four on the verified output filesystem and checks their
actual device/inode identities before launch and after exit. Production noexec
protection therefore covers those writable inherited files as well. The exact
identities are bound into invocation and native observations. Their original
native custody remains a root responsibility. The fourth channel carries the
incremental creation journal.

Metadata-only ELF header inspection rejects initial writable executable load
segments and executable or missing GNU_STACK declarations. The actual interpreter
must occur in the inspected census. The exact header/segment policy is bound into
the native namespace policy and actual preexec receipt. It invokes no ELF code.

The runtime importer records startup/bootstrap scope and validates every ordinary
runtime module before execution, including direct public loaders and extension
creation. Python sources
execute verified bytes. Lifetime records retain modules removed from sys.modules
and are reconciled through completion. Production Landlock covers prebootstrap
native reads and later load/unload attempts, while data/output noexec mounts
prevent native loading from their readable files. Before exec, a concrete seccomp
program rejects every writable executable mmap, including private file mappings,
anonymous executable mmap, mprotect/pkey_mprotect adding execution and personality
changes. The supervisor clears inherited READ_IMPLIES_EXEC before installing it;
the bootstrap rechecks the actual personality. Ordinary reviewed RX mappings
remain permitted. The program also denies ptrace, process_vm_writev, userfaultfd,
io_uring, bpf, perf_event_open, remap_file_pages, ioctl, native fork/vfork,
nonthread clone, memfd and shmat. It rejects alternate x32 syscall numbers.
After bootstrap a second exact filter also denies exec. Both actual receipts bind
PID, architecture, program hash, installation, stage and personality. clone3 returns ENOSYS
for libc's pthread fallback; valid pthread clone remains allowed and included in
worker RSS. Unsupported kernel/architecture or failed installation rejects.
Artifact mode explicitly supplies no kernel or native-loading completeness proof.

Synthetic native evaluator rows retain answer NLL/token/EOS scalars, loss formulas,
bounded saved predictions and token-ID lists, termination metadata, canonical-only
MCQ metrics/candidate scores, aggregates, diagnostics and evaluation envelopes.
Exposure rows retain exact frozen rows, content hashes, native token/progress,

Saved JSON uses native sort_keys, indent=2, ensure_ascii=false, allow_nan=false
and a trailing newline. Exposure JSON uses the native unindented serializer.
Whitespace control padding retains native exact-match scoring while exercising
escape expansion. Separate labelled reserves cover remaining worst-case escaped
prediction/finite-float/stop-token widths, and a four-byte decoded surrogate
covers Unicode object storage without changing the actual prediction or target.
These are conservative synthetic envelopes, not claimed native outcomes or exact
memory equality. Generic loss, similarity subsets and generation/MCQ/teaching/
acquisition timing branches follow native metadata and endpoint conditions.
Baseline generic loss is absent; arm generic evaluation occurs at cursor zero
and the final complete arm endpoint.

The actual saved reporter, final-policy validator, saved-byte/content/aggregate
checks, complete contrasts, influence scores and lane complements run. Only
`verify_preregistered_dependencies` and synthetic `completion_seal` are labelled
fixture eligibility boundaries. Profiles bind counts to exact loaded code objects.
Recursive semantic code identity includes bytecode/constants, compiler settings,

reference/interning encoding. Every one of the six actual loaded production

The final builder probe receives exactly `prepared`, `shared_json_refs`,
`point_report_object`, `point_report_ref`, `n`. It retains the same production

All-n samples require `full_retained_metadata_validation_projection=true`

`n_context="synthetic_analysis_performance_only"`. Full production cost-context

The parent obtains each exact child's through-exit OS RSS via `wait4`, including
serialization/writing/exit. The child's preexit RSS is diagnostic. Parent peak RSS
is separate; their sum is an explicit conservative envelope, not a simultaneous
measured tree peak. An earlier larger child cannot contaminate this child's peak.
CPython subprocess/fork/spawn/exec operations are prohibited in workers and waited

described above, reconciled to the wait4 PID and exact filter program. Original
process/scheduler provenance remains root-owned external evidence. No kernel
certification follows from the artifact tests or an internal approval boolean.

Separate workers perform 32 actual preparation/audit calls and 192 actual digest
reads. Every operation retains order, identity, bytes and elapsed time. The largest
observed operation is the single-operation cost; total worker time is separate.
Repeated physical files and possible warm cache are disclosed. No cold throughput,
future checkpoint existence or independent training replicate follows.

## Retained outputs and remaining gates

Every successful worker retains exact `.input.json`, `.invocation.json`, `.native.json`,
`.result.json`, `.log`, `.observation.json`, `.producer.bin` and
`.custody-journal.bin`. Results are reconciled against an
independent inherited producer channel, exact stdout and original invocation.
Counts, operation maxima, report/policy/registration identities, runtime, source
and memory fields must agree before benchmark and telemetry are exported. Final
builder integration must independently bind actual root invocation, scheduler
allocation/process/native evidence and every exported value.

Worker results and observations use `p4-buffered-worker-result-v6` and
`p4-analysis-performance-worker-observation-v6`. Each observation registers its
own original inode before serialization and retains combined parent/child custody.
Export replay rechecks the original parent, child and observation registries.
Later workers sharing the output include the previous artifacts in their parent
baseline. Final completion writes `analysis-output-custody.json`, including its
own original inode and raw benchmark/telemetry refs, then checks all original
registered chains. This mechanism detects custody changes in writable scratch;
it supplies no external rename-prevention claim.

The separate `p4-worker-custody-journal-v1` channel contains canonical newline
records bound to the exact invocation buffer hash, consecutive sequence and the
previous record hash. The first record binds the exact parent baseline. Each
anchored directory/file/symlink creation emits its original inode immediately
after registration and flushes it with fsync before later work. The journal adds
no permanent descriptor per file and emits one small record per creation rather
than a full inventory per write. A terminal record carries only the original
registered claims. The success terminal and final result must agree exactly.

Caught worker exceptions emit `p4-buffered-worker-failure-v1` with the same exact
nonce/payload/deployment/parent-baseline bindings, original claims and error. The
worker does not scan failure paths to discover original identities. An abrupt
exit can leave a valid journal prefix without a packet or terminal. A syscall
may complete before its journal record flushes, so failed-process original
custody is always explicitly incomplete and unverified as a complete inventory.

Before inspecting the exit code, the parent retains original producer and journal
bytes, parses the valid invocation-bound journal prefix and imports structurally
validated original packet claims without requiring their current paths to match.
It then records current custody discrepancies and rejects nonzero exit. Invalid,
missing, truncated, out-of-order or wrong-binding journal/producer bytes remain
retained, with only the valid preceding claims admitted. A post-failure pathname
scan never becomes original custody. Raw bytes are retained in the failure state
as well as exclusive binary files where current anchoring permits those writes.
The native through-exit observation and traceback log remain evidence of failure.
Zero exit also rejects without the complete successful journal and exact result.
Export replay checks the retained producer, journal and preexec receipt binaries against the original native
bytes. No failure packet, valid prefix or success-labelled record overrides the
actual process exit or supplies benchmark success.

The original preexec receipt is read from the still-open inherited descriptor,
never reconstructed from parsed JSON. The native observation retains its base64
bytes, exact byte length, SHA256, parsed value or parse error, original receipt
channel identity, all four channel identities before launch and after exit,
invocation buffer hash, nonce and policy hash. The parent writes those exact bytes
to `.preexec-receipt.bin`, the ninth worker artifact, and retains them inline in
failure transport if current anchoring prevents a binary write. Export replay
requires exactly one receipt reference, reconciles its bytes with the original
native observation and rechecks its raw hash and original inode custody. Parent
success checks also reconcile the parsed receipt with those original bytes and
retain the existing production PID, invocation, policy, census, filter, ABI and
canonical serialization guards. Artifact mode requires an honestly empty receipt
and no parsed kernel observation.

Malformed, truncated, absent or failed receipts preserve available original
bytes before rejection. A `Popen` preexec callback failure can reap the child
internally before returning a process object. Such a record uses
`p4-internal-native-launch-failure-v1`, `wait4_observation_available=false` and
null PID, exit status and child RSS rather than invented native accounting.
If `Popen` returned a child but a later wait failed, the actual returned PID
remains recorded; absent wait4 status and usage remain null. A labelled external
CPU-watchdog fixture kills and reaps a real child and reports `TimeoutExpired`,
then checks original stdout, producer, journal and receipt prefixes. Its separate
watchdog accounting never becomes the launcher's missing wait4 observation.
Available invocation, receipt, producer and journal bytes still retain their
actual descriptor identities. Failures before channel setup or during channel
capture cannot promise available transport. A captured output-setup failure
before invocation buffering retains available channels with a null buffer hash
and no journal-prefix claims. Failed child custody remains
explicitly incomplete. The CPU fault fixtures write labelled bytes and install
no native kernel policy; they demonstrate retention, rejection and replay only.
The launcher adds no timeout control. An external forced termination of the
supervisor before descriptor capture can destroy anonymous channel bytes. This
successor does not claim crash-durable transport across that boundary; the final
diagnostic owner must retain or disclose unavailable failure evidence.
